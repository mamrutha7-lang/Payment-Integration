# rebuild three months from now resolved a different dependency set than the one
# these tests passed against: the image would drift from the venv silently, and
# the first sign of it would be a production-only failure nobody could reproduce
# locally. These are the versions the suite is green on.
#
# Test-only packages live in requirements-dev.txt. They must NOT be here — this
# file is what `Dockerfile` installs, and pytest in a production image is extra
# attack surface plus a bigger download for nothing.

# Amazon Bedrock (Nova) transport in app/ai/llm.py. The import is lazy — only a

boto3==1.43.80
# Amazon Nova 2 Sonic, the speech-to-speech engine behind INTERVIEW_ENGINE=nova
# (app/interview_nova.py). A SEPARATE package from boto3 and not a duplicate of
# it: boto3 has no InvokeModelWithBidirectionalStream at all — the bidirectional
# API is served only by this experimental smithy-based SDK, which is why AWS's
# own Python samples import it alongside boto3 rather than instead of it.
#
# The import is lazy, for the same reason boto3's is above: it pulls aiohttp and
# the smithy stack in, and a deployment on another engine should not pay that at
# boot. It is DECLARED here anyway, per the api-imports rule.
aws-sdk-bedrock-runtime==0.11.0
# awscrt is what actually CARRIES that stream, and it is not optional.
# aws-sdk-bedrock-runtime does not depend on it, so pip resolves a set that
# imports fine, passes api-imports, and passes every test that fakes the
# upstream — and then refuses the one call the engine exists to make:
# resolve() falls back to the aiohttp transport, which answers
# UnsupportedTransportError to invoke_model_with_bidirectional_stream before
# a packet leaves the process. Not a region problem and not an IAM problem;
# it fails identically on a laptop with no credentials at all.
# The wheel is cp313-abi3, so the 3.14 image installs it without a compiler.
awscrt==0.36.2

# Audio maths for the LOCAL interview engine (app/interview_local.py): RMS for
# the voice-activity gate, and linear resampling between the browser's 24 kHz
# PCM and whatever rate the local models want.
#
# A RUNTIME dependency, not a dev one, and it was missing entirely. The module
# reached main importing numpy with no requirements entry, which is the exact
# failure requirements-voice.txt already carries a warning about and CI has a
# whole `worker-imports` job to prevent for the other process: the import is
# lazy inside a request handler, so the API still BOOTS, and the break only
# surfaces as a ModuleNotFoundError on the first student to use the local
# engine — and as a pytest COLLECTION error, because tests/test_interview_local.py
# imports it at module scope. That takes the whole suite down, not one test.
numpy==2.3.5

# XLSX for the office's spreadsheet imports (B8.1): reading the workbook a
# registrar uploads to `POST /api/admin/imports/preview`, and writing the blank
# templates `GET /api/admin/imports/templates/{kind}.xlsx` hands back. CSV is
# stdlib; .xlsx is not, and .xlsx is what an examination section actually sends.
#
# A RUNTIME dependency, not a dev one, and this pin lands BEFORE the parser that
# needs it. That ordering is the whole lesson of the `api-imports` CI job: the
# parse happens inside a REQUEST HANDLER, so an undeclared openpyxl would let
# the image build, the API boot and every test pass, and would surface as a
# ModuleNotFoundError in front of the first person who ever imported a file — or
# as a pytest COLLECTION error the moment a test module imports the parser at
# module scope, which takes the whole suite down rather than one test. A lazy
# import does not make an undeclared dependency acceptable; it only moves the
# crash. Verified with `python tools/ci/check_api_imports.py`.
openpyxl==3.1.5
