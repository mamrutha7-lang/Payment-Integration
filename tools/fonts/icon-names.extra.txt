# Glyphs the SUBSET must carry that collect-icon-names.py cannot find.
#
# icon-names.txt is GENERATED: the collector rewrites it from the glyph names
# it can see in apps/web/src templates and in the API's SLOT_ICON / SKILL_ICON /
# STATUS_GLYPH constants. That is the right default -- a glyph nobody renders
# should not be paid for in font bytes -- but it cannot cover two cases, and
# both fail SILENTLY, as a blank space where an icon should be:
#
#   1. A glyph the design system requires which no template has reached yet.
#      docs/redesign-2026-09/01-design-system.md §6 names the icon vocabulary
#      for the whole redesign; the screens that use it arrive in Phases 1-4.
#      Without this file each of those phases would have to remember to
#      regenerate the font, and the first one that forgot would ship a screen
#      with holes in it.
#
#   2. A real glyph whose NAME is also an ordinary word, so the collector's
#      denylist (NOT_GLYPHS) throws it away. `block` and `key` are both: the
#      denylist is there to stop `display: block` and dictionary keys becoming
#      font requests, and it cannot tell those from the icons. `block` was
#      already used at six sites -- the practice report's "refused" chip, the
#      interview list, the jobs board twice, the resume policy section and the
#      profile -- and rendered as nothing at all in every one of them.
#
# One name per line. Comments and blank lines are ignored. Adding a name here
# costs a few hundred bytes in the subset; leaving one out costs an invisible
# control on somebody's screen.
#
# Regenerate after editing:
#   python3 tools/fonts/collect-icon-names.py && tools/fonts/fetch-fonts.sh
