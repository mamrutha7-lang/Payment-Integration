Deployment · AWS via CDK

The interview's path through AWS

Where the audio actually travels, why the model sits in a different country from the servers, and what that costs in milliseconds a student can feel.

1 · The deployment

CloudFront in front, an ALB doing the WebSocket upgrade, and Fargate behind it — split into two services, because the thing that breaks interviews today is a deploy draining an HTTP API on a timer far shorter than a call. Everything below is CDK; Terraform is being retired.

Live bug, todayECS stopTimeout is unset anywhere in the infrastructure, so Fargate defaults to 30 seconds and the Dockerfile's --timeout-graceful-shutdown 110 is unreachable. Against a 480-second interview, every deploy kills every live call. Target-group deregistration_delay is 30 s for the same reason. Fix both before anything else here.

2 · What a student actually waits

The number that matters is mouth to ear: the end of their last syllable to the first syllable of the interviewer's reply. Below ~800 ms feels like conversation. Past ~1,200 ms students start talking over the model, which trips the barge-in gate, which then has to arbitrate — and that arbitration is the "glitchy" feeling.

The honest headline≤800 ms is not reachable on this architecture — the model's own floor is around 650 ms at its best and about 1,025 ms typically. A realistic target is 1,000–1,200 ms, and the cross-region hop is what pushes the typical case over that line. Anyone promising "sub-second" is promising something the model does not do.

3 · The levers, in order of return

  • Move the stack to a region that serves Nova 2 Sonic — worth ~124 ms per turn, every turn, and it is the single largest thing under your control. The alternative is accepting Mumbai↔Tokyo permanently. (The code already documents the handshake as "~1-2 s from ap-south-1 to Tokyo".)
  • Keep the socket off CloudFront — a dedicated wss:// host straight at the ALB saves a POP hop; CloudFront still serves the SPA and the REST API.
  • Never put API Gateway in front of this. It is not a WebSocket proxy, it adds 55–220 ms of round trip, and the session cookie does not survive the domain change — every interview would close 1008.
  • Tune nova_sonic_endpointing with care. It is the one model-side dial, and it trades latency against cutting students off mid-sentence. Change it on evidence, not hope.
  • Do not shrink the jitter buffer. The 140 ms floor is what stops the audio clicking; it grows adaptively to 300 ms precisely because underruns sound worse than delay.

4 · The other clock: an interview is not 15 minutes

Bedrock closes the stream at 8 minutes, and the engine treats that as the real cap rather than discovering it mid-verdict.
