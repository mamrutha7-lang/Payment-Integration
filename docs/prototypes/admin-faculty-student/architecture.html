Implementation blueprint

The institutional spine

Four mechanisms to build, drawn as they will actually work. Each one closes a gap where the design assumes a link the database does not make — and where the missing piece is a write path, not a screen.

1 · The one edge that changes everything

The student's locked profile card shows five institutional facts. Four of them are unreachable today, because the column that should join a student to their batch is a bare string that nothing validates. Promote it to a real foreign key and all five arrive through one join — no new columns on students.

Why not just add the columns?Copying College, Department, Batch and the two dates onto students looks faster and is the trap. It creates two sources of truth, and it is what makes the deferred levels expensive later — see the next figure.

2 · Where academic year, course and specialization slot in

These were left out deliberately. Because a student holds one key and everything else is read through it, each future level is a new table and one foreign key — and no existing student row is touched.

3 · Provisioning: turning a dead end into a flow

Approval today writes a status and three audit columns and creates nothing. Its own docstring calls provisioning "a deliberate follow-up step" — and that step exists nowhere in the codebase. This is where it goes.

Credential caveatIn production sign-in is Google-only — POST /api/auth/login is refused when ENV=prod. A generated passphrase is the dev/CI door and the break-glass account. The production first-sign-in is a Google invite against the same provisioned row; both paths end at the identical users record.

4 · Access: grants narrow, they never widen

The capability check is a new gate placed after the existing scope rule, not instead of it. That ordering is the whole safety argument: a grant can only subtract from what the role already allowed, so no grant can hand someone a student that rule 2 would have refused.

Do not fold rule 2 inIt is tempting to replace assert_student_scope with a view_students capability. Don't. That gate is the one place the "a mentor with no group sees nobody" rule lives, and it is enforced at 25 call sites. The capability layer sits on top of it.

What this does not cover

Two tracks run beside this one and are unchanged by it:

  • Design import — Agent Voice (931 structural diff lines), Login, Faculty Leave, Resume Builder, Leave Approvals, and the four Mentor→Faculty screen renames. Twelve screens are byte-identical and must not be touched.
  • Deployment (CDK-only) — including one live bug: ECS stopTimeout is unset, so a deploy SIGKILLs at 30 s against 480 s interviews. And retiring Terraform requires terraform state rm across all 78 resources before the .tf files are deleted, or a later apply destroys the database.
